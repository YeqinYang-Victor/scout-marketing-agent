### 关键设计原则

| 原则 | 体现 |
|------|------|
| **配置与代码分离** | 数据源、筛选规则、模板、品牌视觉全部放在 `config/*.json`，改配置不需要改代码 |
| **业务与 AI 解耦** | 流水线默认用规则引擎跑通，大模型只是可选增强层，调用失败自动回退 |
| **零原生依赖可运行** | Agent SDK 按需动态加载；SQLite 缺失时自动回退 JSON 存储 |
| **每一步可观测** | `runPipeline` 每步回调 `onStep`，前端用 SSE 实时展示进度 |

## 二、数据流详解

```
数据源 (JSON/HTML/RSS)
   │  fetchers.ts        按字段映射提取 → RawEvent[]
   ▼
normalize.ts              清洗 HTML、统一时间、计算 ageHours → NormalizedEvent[]
   ▼
scorer.dedupe()           标题相似度 ≥0.82 合并
   ▼
trading-calendar.ts        A 股交易日历（交易日判定 / 最近 N 个交易日 / 滞后检测）
   ▼
scorer.applyHardFilters() 排除词 / 热度 / 最近 N 个交易日窗口 / 行业黑名单
   ▼
scorer.scoreAndRank()     五维加权 + 关键词加减分 → ScoredEvent[]
   ▼
scorer.selectTop()        取 TopN（默认 1）
   ▼
writer.generateFieldsByRules()  或  llm.generateFieldsWithLLM()
   │                      产出 ReportFields（影响解读/产业链/受益方向/风险提示…）
   ▼
writer.renderTemplate()   模板引擎渲染 → ReportDraft
   ▼
banner.generateBanner()   品牌配置 + 事件数据 → SVG / PNG
```

## 三、二次开发场景

### 场景 1：接入真实订阅站（URL + 账号密码）

编辑 `config/data-sources.json`，或直接在「数据源配置」页填写。最简形态：

```jsonc
{
  "id": "my-subscription",
  "name": "XX金融资讯站",
  "type": "http-login",
  "enabled": true,
  "config": {
    "authMode": "cookie",
    "loginUrl": "https://site.com/api/login",
    "loginMethod": "POST",
    "loginContentType": "application/json",
    "loginBody": { "username": "{{username}}", "password": "{{password}}" },
    "credentials": { "username": "你的账号", "password": "你的密码" },
    "listUrl": "https://site.com/api/hot?date={{date}}&limit=50",
    "listMethod": "GET",
    "headers": { "User-Agent": "Mozilla/5.0" },
    "parser": {
      "kind": "json",
      "itemsPath": "data.list",
      "fieldMap": {
        "title": "title", "summary": "digest", "url": "link",
        "publishedAt": "publish_time", "heat": "hot_value",
        "sectors": "sectors", "stocks": "related_stocks"
      }
    }
  }
}
```

然后把 `activeSourceId` 改成 `my-subscription`（或在界面上点「设为默认数据源」）。

**调试技巧**：先只填 `loginUrl` + `listUrl`，跑一次 `npm run pipeline`，看日志里的
`登录成功（Cookie 已获取）` 与 `订阅源返回 N 条事件`，再逐步补字段映射。

#### 常见「疑难站点」的应对套路

真实订阅站往往不是标准的「JSON 登录 + 扁平列表」。以下是在接入
「示例金融数据源」时实际踩到并已支持的几类情况，可作为排查清单：

**① 站点是 SPA，接口在另一个域名**

前端页面只有一个空 `<div id="app">`。此时去拉页面引用的 JS 包，
在里面搜 `baseURL`、`"/login"`、接口路径字符串，就能定位真实 API 域名与端点。

**② 登录是 multipart 表单**

```jsonc
"loginContentType": "multipart/form-data",
"loginBody": { "name": "{{username}}", "pwd": "{{password}}" }
```

注意字段名未必是 `username` / `password`。适配器会用 `FormData` 发送，
并**自动省略手工设置的 Content-Type**（否则 boundary 会缺失，服务端解析失败）。

**③ 登录失败也返回 HTTP 200**

业务错误码藏在响应体里，需要显式校验：

```jsonc
"successCodePath": "retCode",   // 取 data 里的字段路径
"successCode": "000",           // 期望值
"messagePath": "retMsg"         // 失败时用于拼错误信息
```

**④ Token 直接放 Authorization，不带 Bearer 前缀**

```jsonc
"authMode": "header",           // cookie | bearer | header
"tokenPath": "data.token"
```

**⑤ 列表是嵌套结构（事件 → 板块 → 个股/ETF）**

```jsonc
"parser": {
  "kind": "json",
  "itemsPath": "",                        // 空字符串 = 响应本身就是数组
  "fieldMap": { "title": "eventName", "publishedAt": "eventDate" },
  "sectorListPath": "sectorList",
  "sectorFieldMap": { "name": "sectorName", "change": "increase", "remark": "sectorRemark" },
  "securityListPath": "securityList",
  "securityFieldMap": { "name": "name", "code": "code", "change": "increase" },
  "etfListPath": "etfList",
  "etfFieldMap": { "name": "name", "code": "code", "change": "increase" }
}
```

映射后会自动填充 `sectorDetails` / `securityDetails` / `etfs`，
并把 `sectors` / `stocks` 投影成扁平数组，下游打分与文案逻辑无需改动。
其中 `sectorRemark`（板块传导说明）会被优先用作文案的「影响解读」。

**⑥ 源没有热度字段 / 涨跌幅口径不同**

用 `derive` 从已有字段派生：

```jsonc
"derive": {
  "marketChange": "maxSectorChange",   // maxSectorChange | maxAbsSectorChange | avgSectorChange
  "heatPerPercent": 200000,            // 1% 涨跌幅 ≈ 20 万热度（替代口径，非真实热度）
  "summaryFrom": "sectorReaction",     // sectorReaction | sectorRemark
  "contentFrom": "allSectorRemarks"
}
```

**⑦ 不想反复请求真实站点**

```jsonc
"cache": { "ttlMinutes": 720 }
```

首次请求后快照落盘到 `server/data/cache/`，TTL 内**连登录请求都会跳过**。
需要强制刷新时删掉缓存文件，或临时把 `ttlMinutes` 调小。

**⑧ 凭据不要写进配置文件**

```jsonc
"credentials": { "username": "${MY_USER}", "password": "${MY_PASS}" }
```

真实值放项目根目录的 `.env`（已被 `.gitignore` 忽略）。适配器会自动把
`${VAR}` 解析成环境变量，配置文件里只留占位符。

> 提示：如果站点改版导致抓取失败，优先用浏览器开发者工具的 Network 面板
> 复现一次请求，核对端点、请求体字段名与鉴权头，再回填到配置里。

### 场景 2：新增一个数据源类型

在 `server/pipeline/fetchers.ts` 中：

```ts
async function fetchMyApi(source: DataSource, ctx: FetchContext): Promise<FetchResult> {
  const resp = await fetch(source.config.endpoint);
  const json = await resp.json();
  return { events: json.data.map(toRawEvent) };
}

export async function fetchFromSource(source, ctx) {
  switch (source.type) {
    case 'mock':       return fetchMock(source, ctx);
    case 'http-login': return fetchHttpLogin(source, ctx);
    case 'rss':        return fetchRss(source, ctx);
    case 'my-api':     return fetchMyApi(source, ctx);   // ← 新增
  }
}
```

同时更新 `types.ts` 里 `DataSource['type']` 的联合类型与前端下拉选项。

### 场景 3：调整打分维度

**改权重/阈值**：直接在「筛选规则」页拖滑块，或改 `config/filter-rules.json`。

> **换数据源后建议重新校准。** 权重的合理性取决于各维度在**当前数据源**上的区分度。
> 例如接入「示例数据源」后发现：每个事件固定 3 个板块 → 「行业覆盖面」几乎是常量，
> 区分度有限；而「时效性」在交易日窗口内区分度很高。
> 因此把权重调成 38 / 12 / 26 / 14 / 10，半衰期取 12h 并加 15 分「当日发布」加成。
>
> 校准方法：跑一次 `npm run pipeline`，看 `server/data/runs/*.json` 里
> `candidates[].breakdown` 各维度的取值分布。若某维度几乎所有事件都取同一个值，
> 说明它在这个源上没有区分度，应当降权或改 `params` 里的天花板值
> （如 `heatCeiling`、`changeCeiling`、`sectorCeiling`）让它用满 0–100 区间。

**关于满分触顶**：`ScoredEvent` 同时保存 `totalScore`（裁剪到 0–100，用于展示）
与 `rawScore`（未裁剪，用于排序）。排序按 `rawScore` 进行，因此多个事件同时触顶
100 时仍能保持稳定次序，不会退化成「并列」。

**新增一个维度**（例如「资金流向」）：

1. 在 `filter-rules.json` 的 `dimensions` 加一项：
   ```json
   { "key": "capitalFlow", "label": "资金流向", "weight": 0.1, "enabled": true,
     "params": { "northboundCeiling": 100 } }
   ```
2. 在 `scorer.ts` 的 `scoreDimension()` 加一个 `case 'capitalFlow'`：
   ```ts
   case 'capitalFlow': {
     const ceiling = params.northboundCeiling ?? 100;
     const flow = Number((e as any).northbound ?? 0);      // 需在 fetcher 里带上该字段
     const score = clamp((Math.abs(flow) / ceiling) * 100);
     return { score, detail: `北向净流入 ${flow} 亿` };
   }
   ```
3. 记得把各维度权重重新配平到 100%。

### 场景 4：新增/修改文案模板

在「文案模板」页新建模板即可，`body` 支持：

| 语法 | 说明 |
|------|------|
| `{{变量}}` | 插值。内置变量见页面底部提示 |
| `{{#each 数组}} ... {{/each}}` | 循环，内部用 `{{this}}` 或 `{{this.name}}` |
| `{{#if 变量}} ... {{/if}}` | 条件渲染 |

模板的 `fields` 声明了需要产出哪些内容字段。若使用大模型润色，
`fields[].prompt` 会作为写作要求一并送给模型。

### 场景 5：调整 Banner 版式

版式在 `server/pipeline/banner.ts` 的 `buildBannerSvg()` 中，用字符串拼 SVG。
颜色、尺寸、Slogan、免责声明来自 `config/brand.json`，一般无需改代码。

坐标系（默认 1080×608）：

| 区域 | y 范围 | 内容 |
|------|--------|------|
| 品牌栏 | 0–96 | 券商名 · 产品名 / 日期 |
| 事件标签 | ~148 | `TODAY'S EVENT` + 热度徽标 |
| 标题 | 190–330 | 最多 3 行，40px 粗体 |
| 行业标签 | 340–384 | 最多 4 个，自动防溢出 |
| 产业链三栏 | 410–534 | 上游 / 中游 / 下游 |
| 合规栏 | 548–608 | 引导语 + 免责声明 |

### 场景 6：接入合规词库

在 `writer.ts` 的 `composeDraft()` 返回前加一道校验：

```ts
const BANNED = ['必涨', '稳赚', '保本', '包赚'];
const hit = BANNED.find((w) => text.includes(w));
if (hit) throw new Error(`文案命中违规词：${hit}`);
```

更完整的做法是接入公司合规系统 API，把校验结果写入 `run` 记录。

### 场景 7：调整时效窗口 / 维护交易日历

筛选窗口**不是按小时**，而是按 **A 股交易日**：

```jsonc
"hardFilters": {
  "minHeat": 0,
  "requireSectors": false,
  "maxTradingDays": 2,        // 保留最近 2 个交易日
  "maxStaleTradingDays": 1    // 数据源最多滞后 1 个交易日，超过则判停更并报错
}
```

**为什么不用小时**：主数据源的日期字段是 UTC 零点（= 北京时间 08:00）。
若按「48 小时」硬切，周五 08:00 的条目到周日 08:00 就过期，
于是周六下午起、整个周日、周一早晨都会产出为空 —— 而周一早晨正是最需要出稿的时点。

**交易日历**在 `config/trading-calendar.json`，由 `tools/build-trading-calendar.ts` 生成：

```bash
npm run build:calendar     # 重新生成（次年放假安排公布后执行）
npm test                   # 回归测试
```

维护要点：
- 规则是「**周一至周五 且 非法定节假日**」。⚠️ 调休「补班」的周末**股市不交易**，
  不能按「工作日」判断；
- 未覆盖的年份退化为「周一至周五均为交易日」，界面与 `GET /api/scout/calendar`
  会显示当前覆盖年份；
- 若要换成公司内部交易日历源，只需保持 `{ coveredYears, holidays: { 'YYYY-MM-DD': '名称' } }`
  的结构，替换 `trading-calendar.ts` 的加载逻辑即可。

**窗口基准日**取「数据源中最新一条所在的交易日」，而不是「今天」——
交易日上午（尤其周一 7:30）当日数据尚未产生，以今天为基准会让窗口退化成只剩 1 天。

## 四、API 参考

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/health` | 健康检查，返回当前持久化后端 |
| GET | `/api/scout/meta` | 一次性返回 brand / sources / rules / templates |
| GET | `/api/scout/config/:name` | 读取单项配置（`brand`/`sources`/`rules`/`templates`） |
| PUT | `/api/scout/config/:name` | 覆盖保存配置 |
| POST | `/api/scout/run` | 同步跑一次流水线，返回完整 `PipelineRun` |
| GET | `/api/scout/run/stream` | **SSE** 跑流水线，逐条推送 `{type:'step'}`，最后 `{type:'result'}` |
| GET | `/api/scout/calendar` | A 股交易日历状态（今天是否交易日、最近交易日、最近 5 个交易日） |
| GET | `/api/scout/runs` | 运行记录列表（摘要） |
| GET | `/api/scout/runs/:id` | 单次运行详情 |
| POST | `/api/scout/recompose` | 用同一头号事件换模板重新生成文案 |
| GET | `/api/scout/banners/:file` | Banner 静态资源（svg/png） |

`run/stream` 支持的 query 参数：`sourceId`、`templateId`、`useLlm`、`model`、`topN`。
