# 开源选型评估报告

> 目标：为「券商营销文案自动化生产 Agent（产业链侦察兵日报）」选定可复用的基础项目。
> 检索时间：2026-10-06 ｜ 数据来源：GitHub API（`api.github.com`）实时读取

---

## 一、需求拆解与技术诉求

把业务需求拆成 5 个技术能力，作为选型的评估维度：

| # | 能力 | 说明 | 权重 |
|---|------|------|------|
| C1 | **多源数据采集** | 支持 URL + 账号密码登录、Cookie/Token 鉴权、JSON/HTML/RSS 解析 | 高 |
| C2 | **事件筛选与排序** | 可配置的多维打分（市场影响力、行业覆盖、时效性…） | 高 |
| C3 | **LLM 文案改写** | 把结构化事件改写成可直接转发的营销文案 | 中 |
| C4 | **模板管理** | 文案模板可配置、可增删、多版本 | 高 |
| C5 | **图片/Banner 生成** | 自动生成 App 首页投放图 | 中 |
| C6 | **可交互的应用外壳** | 客户经理/运营可直接使用的界面 | 高 |

关键约束：
- 数据源当前只能用 **URL + 账号密码** 登录，后续才换 API ⇒ 采集层必须**可插拔**；
- 面向**券商合规**场景，文案与图片的**文字准确性**是硬要求（不能用 AI 生图瞎画中文）；
- 需要交付一个**能跑起来的应用**，而不是一堆脚本。

## 三、评估结论

### 3.1 为什么不用 GitHub 上的 Python 项目直接做基础

1. **形态不匹配**：上述项目都是「脚本 + 定时任务 + 推送」，没有可交互的应用外壳（C6），而本项目需要给客户经理/运营用的界面；
2. **数据源不可插拔**：`ai-aggregator-report` 的 `fetchers/` 设计很好，但适配器是硬编码的（HackerNews、arXiv、GitHub Trending…），**没有「账号密码登录订阅站」这一类**（C1）；
3. **技术栈割裂**：Python 后端 + 需要另建前端，交付周期长；且无法直接复用 Agent SDK 的会话/权限/流式能力；
4. **合规风险**：营销文案 + App 投放图对文字准确性要求高，AI 文生图方案不可靠。

### 3.2 最终方案：**以官方 Agent 应用脚手架为基础，借鉴开源项目的架构设计**

| 模块 | 来源 | 复用方式 |
|------|------|----------|
| **应用外壳 / 后端服务 / Agent 集成** | `codebuddy-chat-web` 脚手架（场景自带） | ✅ **作为基础项目直接落地**，在其上做个性化修改 |
| **采集层分层设计**（`fetchers/` 每源一个适配器 + 统一入口） | `liuyueyi/ai-aggregator-report` | 📐 **借鉴架构**，用 TypeScript 重写为 `server/pipeline/fetchers.ts`，并新增 `http-login` 适配器 |
| **去重 + 事件评分 + 排序** | `DemonDamon/FinnewsHunter`、`mizid0402-ops/finance-daily` | 📐 **借鉴思路**，实现为可配置的五维加权打分模型 `server/pipeline/scorer.ts` |
| **Banner 渲染** | `vercel/satori` 的替代思路 | 🔧 **自研模板化 SVG 渲染**（见下） |

### 3.3 关于 Banner 的技术决策

评估过 `satori`，最终**没有直接采用**，原因：

1. satori 渲染中文需要额外打包 CJK 字体文件（10MB+），且字体缺失时中文会变成豆腐块；
2. 本项目的 Banner 版式**高度固定**（品牌栏 + 标题 + 行业标签 + 产业链三栏 + 合规栏），用**纯 SVG 字符串模板**即可实现，零额外依赖、零字体风险；
3. SVG 是矢量格式，任意分辨率都清晰，且品牌色/字体 100% 可控；
4. 需要位图时，用 `sharp` 服务端转 PNG（失败自动降级为仅 SVG）。

> 参考实现见 `server/pipeline/banner.ts`。

## 四、改造后的架构

```
营销文案生成agent/
├── config/                       ← ★ 四类业务配置（用户可改，无需改代码）
│   ├── data-sources.json             ① 数据源配置（URL + 账号密码 / RSS / 演示）
│   ├── filter-rules.json             ② 筛选规则（五维权重、阈值、关键词）
│   ├── templates.json                ③ 文案模板库（产业链侦察兵多版本）
│   └── brand.json                    ④ 品牌视觉（Banner 用）
│
├── server/
│   ├── index.ts                   ← 脚手架：Express + SSE + Agent SDK
│   ├── db.ts                      ← 脚手架：SQLite 会话持久化
│   ├── api.ts                     ← 新增：业务 REST API（/api/scout/*）
│   ├── cli.ts                     ← 新增：命令行跑流水线（可接 cron）
│   └── pipeline/                  ← 新增：核心业务流水线
│       ├── fetchers.ts                数据源适配器（mock / http-login / rss）
│       ├── normalize.ts               标准化
│       ├── scorer.ts                  去重 + 硬过滤 + 五维打分 + 排序
│       ├── writer.ts                  模板引擎 + 规则引擎字段生成
│       ├── llm.ts                     Agent SDK 大模型润色（可选，失败自动回退）
│       ├── banner.ts                  Banner SVG/PNG 生成
│       ├── knowledge.ts               产业链 & 个股知识库
│       └── run.ts                     流水线编排（带进度回调）
│
└── src/                          ← 前端（React + TDesign + Tailwind）
    ├── App.tsx                        应用外壳 + 左侧模块导航
    ├── api/scout.ts                   业务 API 客户端
    └── pages/
        ├── ScoutDashboard.tsx         ① 工作台：一键生成 + 打分看板 + 文案 + Banner
        ├── SourcesPage.tsx            ② 数据源配置 + 品牌视觉
        ├── RulesPage.tsx              ③ 筛选规则
        ├── TemplatesPage.tsx          ④ 文案模板管理 + 预览
        └── AgentPage.tsx              Agent 对话（自然语言驱动）
```

### 四大核心模块的落地方式

| 需求 | 落地 |
|------|------|
| **数据源配置** | `config/data-sources.json` + `SourcesPage` 可视化编辑；新增数据源只需加一条 JSON，不改代码 |
| **筛选规则自定义** | `config/filter-rules.json` + `RulesPage` 滑块调权重、改阈值、维护关键词表 |
| **文案模板管理** | `config/templates.json` + `TemplatesPage` 增删模板/字段，自带模板引擎与预览 |
| **Banner 自动生成** | `config/brand.json` 控制品牌视觉，`banner.ts` 自动排版出图，支持 SVG/PNG 下载 |

## 五、后续演进建议

1. **数据源**：待订阅站开放 API 后，在 `data-sources.json` 新增一个 `type: "api"` 适配器即可切换，业务代码零改动；
2. **筛选模型**：可把五维权重交由业务方按月回测调优（当前为经验值）；
3. **文案质量**：配置 `CODEBUDDY_API_KEY` 后开启「大模型润色」，文案自然度显著提升；
4. **合规**：建议接入内部合规词库，在 `writer.ts` 出口增加敏感词校验；
5. **定时任务**：用 `npm run pipeline` 配合 cron / CI，实现每日 7:30 自动产出。
